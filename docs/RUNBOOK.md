# Proposed production alert and rollback runbook

If deployed, alert on `incident_agent_request_failure_rate`: the fraction of investigation requests ending in an API error, timeout, invalid structured response, or invalid citation. Page the project's designated on-call owner when this rate exceeds 5% over 10 minutes with at least 20 requests. Until the team assigns a rotation, the repository owner is the proposed responder (name/contact must be confirmed before production). The responder checks per-request errors, latency and token usage without logging credentials, then compares the current manifest and CI result with the last accepted release. Rollback means redeploying the last accepted Git commit together with its pinned model snapshot, prompt, evidence corpus, schema, tool definitions and settings; restore the baseline belonging to that release and run smoke and gate checks. Never regenerate a baseline to conceal a regression, and never restart, roll back, or reconfigure the investigated services through this agent. If the pinned model is unavailable, disable model-backed investigation and surface an availability error until a replacement is evaluated. This alert is a proposed operational policy, not an installed monitoring integration; deployment and paging are outside this minimal homework build.
